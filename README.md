# Портал документации — веб-портал для хранения корпоративной документации

Внутренний веб-сервис компании: документы (файлы любых форматов и страницы, написанные
в редакторе) хранятся в дереве разделов любой вложенности; модераторы разделов публикуют
документы и загружают новые версии, все старые версии сохраняются; портал следит за сроком
актуальности каждого документа, рассылает уведомления и ведёт полную статистику просмотров,
скачиваний и изменений. Вход — по локальным учётным записям и/или через Active Directory (LDAP).
Оформление выполнено в стиле сайта vodokomfort.ru (фирменный логотип и шрифты DIN Condensed
и Roboto входят в поставку).

* Стек: PHP 8.2+, Symfony 7.4 LTS, MySQL 8 / MariaDB 10.6+, nginx, редактор Quill.
* Полное руководство (методология, установка, настройка, использование, эксплуатация):
  **docs/РУКОВОДСТВО.md** (и docs/РУКОВОДСТВО.docx).

## Возможности

| Возможность | Кому доступна |
|---|---|
| Просмотр дерева разделов и открытых опубликованных документов без входа — отовсюду, только из указанных подсетей или выключено (настраивается в панели администратора); документы только для сотрудников помечаются как внутренние | гостям |
| Разделы любой вложенности, карточки разделов с описанием и счётчиками | всем (просмотр) |
| Документы-файлы (PDF, Word, Excel, чертежи, архивы…) и документы-страницы (текст в редакторе) | всем (просмотр опубликованных) |
| Версии: каждая загрузка/правка — новая версия; старые версии открываются, скачиваются, сравниваются | всем |
| Срок актуальности: значки «актуален / истекает / просрочен», уведомления ответственным по почте | всем / модераторам |
| Поиск по названию, номеру, описанию, тегам, имени файла и тексту страниц | всем |
| Создание, публикация, архив, восстановление версий, удаление документов; подразделы | модераторам своих разделов |
| Статистика по документу: просмотры, скачивания, читатели, график активности, журнал | модераторам / администраторам |
| Раздел администратора: дерево разделов, модераторы, пользователи, реестр документов, вся статистика с выгрузкой CSV, журнал событий, настройки | администраторам |
| Актуальность по разделам: дерево разделов с просроченными и истекающими документами, список устаревших по разделам и ответственным, CSV | администраторам |
| Импорт из каталога на диске сервера: дерево папок → дерево разделов, файлы → документы; предпросмотр плана, повторный импорт добавляет версии изменившихся файлов | администраторам |
| REST API `/api/v1` для внешних систем: разделы, документы, извлечённый текст (страницы, PDF, docx/xlsx/pptx, odt…), файлы, лента изменений для инкрементальной синхронизации RAG-индекса; ключи API, webhook об изменениях | внешним системам / администраторам |
| Описания документов через внешнюю LLM (OpenAI-совместимый API: OpenAI, OpenRouter, Ollama, LM Studio, vLLM…): кнопка в карточке, автоописание новых и импортируемых документов, массовая команда | модераторам / администраторам |
| Вход через Active Directory / LDAP с автосозданием учётных записей, группы AD для доступа и прав администратора | — |
| Настройки в панели администратора: режим просмотра без входа и список разрешённых IP-адресов и подсетей | администраторам |
| Скрипты установки/обновления/резервного копирования, Docker Compose, консольные команды | администратору сервера |

## Установка на чистый сервер одной командой

```bash
tar -xzf docportal-1.3.0.tar.gz && cd docportal
sudo ./deploy/install.sh                                   # nginx + PHP-FPM + MariaDB на этом сервере
sudo ./deploy/install.sh --domain docs.example.ru --ssl-email it@example.ru \
     --ldap-host dc1.example.local --ldap-base-dn "DC=example,DC=local" --ldap-upn-suffix example.local
sudo ./deploy/install.sh --mode docker                     # в контейнерах Docker Compose
```

Поддерживаются Debian 11/12/13, Ubuntu 22.04/24.04/26.04 (AlmaLinux/Rocky 9 — экспериментально).
Переносите на сервер именно архив дистрибутива: в нём есть `vendor/` (зависимости), поэтому
Composer и доступ к packagist.org на сервере не нужны. Полный список параметров: `./deploy/install.sh --help`.

## Управление после установки

```bash
docportal status                      # диагностика
docportal backup                      # резервная копия (БД + файлы + настройки)
docportal update                      # обновление (запуск из каталога новой версии: sudo ./deploy/update.sh)
docportal restore /var/backups/docportal/<архив>.tar.gz
docportal console app:user:create ivanov --name "Иванов И.И." --generate
docportal console app:ldap:test ivanov       # проверка входа через домен
docportal console app:documents:expiry       # проверка сроков и рассылка уведомлений (по cron ежедневно)
docportal import /mnt/share/Документы --dry-run   # импорт из каталога: папки → разделы, файлы → документы
                                             # (без --dry-run — выполнить; в панели администратора: «Импорт»)
docportal api-key create "Индексатор RAG"    # ключ REST API для внешней системы (или панель администратора → Интеграции)
docportal describe --missing --limit=50      # описания документов через LLM (настройки — в «Интеграциях»)
docportal uninstall                   # удаление (с --purge — вместе с базой данных)
```

## Запуск для разработки

```bash
composer install
cp .env.local.example .env.local     # укажите DATABASE_URL и APP_SECRET, APP_ENV=dev
php bin/console doctrine:migrations:migrate -n
php bin/console app:user:create admin --admin --generate
php bin/console app:demo:load        # демонстрационные разделы, пользователи (пароль Demo12345) и документы
./scripts/dev-server.sh              # http://127.0.0.1:8080
```

Автотесты: `php vendor/bin/phpunit` (нужна база `docportal_test`, см. `.env.test`).
Сквозная проверка через браузер и скриншоты: `python3 tests/e2e_screens.py http://127.0.0.1:8080 docs/images var/import [http://127.0.0.1:8090/v1]`
(третий аргумент — каталог импорта проверяемого сервера, четвёртый — адрес заглушки LLM `python3 tests/mock_llm_server.py 8090`).

REST API для внешних систем: `curl -H "Authorization: Bearer dp_…" http://127.0.0.1:8080/api/v1/documents` —
описание в руководстве (приложение «REST API для внешних систем (RAG)»).

## Структура проекта

| Каталог | Назначение |
|---|---|
| `src/Entity/` | модель: пользователи, разделы (дерево), модераторы, документы, версии, события |
| `src/Controller/` | страницы: вход, разделы, документы, поиск, профиль; `Admin/` — панель администратора; `Api/` — REST API `/api/v1` |
| `src/Service/` | документы и версии (`DocumentManager`, `FileStorage`), разделы (`SectionManager`), актуальность (`Validity`, `ExpiryNotifier`), статистика (`StatsService`), пользователи (`UserManager`), настройки (`PortalSettings`), импорт из каталога (`Import/`), извлечение текста (`Text/`), LLM (`Llm/`), webhook и представление API (`Integration/`), HTTP-клиент (`Http/`) |
| `src/Security/` | аутентификатор (локальные + LDAP), правила доступа (`Access`), voter, гостевой доступ, клиент LDAP; `Api/` — ключи API |
| `src/Command/` | консольные команды `app:*` (пользователи, проверка, сроки, LDAP, импорт, ключи API, описания через LLM, демо-данные) |
| `templates/`, `public/css`, `public/js`, `public/vendor/quill` | интерфейс (Twig, CSS, JS без сборки, редактор страниц) |
| `deploy/` | скрипты установки, обновления, резервного копирования, диагностики, удаления |
| `docker/` | Dockerfile, docker-compose.yml, nginx, PHP и планировщик для контейнеров |
| `docs/` | руководство, схемы, скриншоты |
| `tests/` | автотесты PHPUnit и сквозная проверка через браузер |
